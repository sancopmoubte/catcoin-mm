# 猫猫币正式网候选：链上免费领取模块设计与不可兼容项

本设计把用户确认的规则转化为 Cosmos SDK 状态机要求：总量固定 21,000,000 MM、8 位精度、3 MM 启动质押加其余领取池、首笔 `1umm`（0.00000001 MM）、每满 24 小时翻倍、单地址累计封顶 1 MM、每 UTC 日全网最多从领取池分发 210 MM、交易费为 0。它已作为本仓库追踪的独立候选应用 `chain/catcoin-app/x/claim` 实现并通过隔离节点回归；它仍不是已上线的正式网络。

## 链上状态与交易

自定义 `x/claim` 模块使用 Protobuf 消息、keeper 和 KV 状态，而不是网页 localStorage 或一个公开助记词。Cosmos SDK 的交易消息带签名者注解，消息处理后写入确定性状态；所有验证者会对同一消息执行同一状态机并得到同一 AppHash。[1] [2]

| 状态或消息 | 链上内容 | 不可绕过的约束 |
|---|---|---|
| `ClaimRecord[address]` | `claimed_umm`、`claim_count`、`last_claim_unix` | 地址累计不得超过 `100000000umm`（1 MM） |
| `UsedCredential[credential_id]` | 已消费的一次性资格编号 | 任一编号只能在成功领取交易中写入一次；跨地址重放必须拒绝 |
| `ClaimAuthority` | `issuer_key_id → Ed25519 公钥`、吊销状态与生效高度 | 创世只写公钥；签发私钥不得写入链、仓库、钱包或节点 |
| `DailyDistribution` | 当前 UTC 日编号、当日已分发的 `umm` | 固定上限为 `21000000000umm`（210 MM）；区块时间回退或同日超额均拒绝，次日首次成功领取时重置计数 |
| `ClaimPool` | 模块账户或受控领取池地址的可用余额 | 创世存 `2099999700000000umm`（20,999,997 MM）；不得拥有 mint 权限 |
| `MsgClaim` | `claimer` 为唯一交易签名者；带 `voucher`（链 ID、地址、资格编号、过期时间、签发公钥编号、签名） | 请求不携带可自定金额；凭证地址必须等于 `claimer`，且链 ID 必须等于当前链 |
| 链上转账 | 从领取池转入 `claimer` | 领取池余额不足即拒绝；不得调用 `MintCoins` |
| 查询接口 | 地址已领数量、下一次可领数量、可领取时间、池余额、当日额度/已分发额 | 钱包只展示链上返回值，不自行计算可用资格或每日计数 |

资格服务只在完成发行方确定的唯一性审核后签发凭证。凭证的规范待签名字节固定为 `catcoin.claim.v1|chain_id|address|credential_id|expires_at|issuer_key_id`，并由 Ed25519 公钥验证。该域分隔符和链 ID 绑定可防止凭证在其他消息类型、其他地址或其他网络重用。Go 标准库的 Ed25519 `Verify` 可用于该公钥验签；正式模块实现必须使用与候选规则包相同的规范编码。[3]

`MsgClaim` 的 keeper 必须按如下原子顺序执行：验证交易签名者；验证凭证的链 ID、地址、过期时间、签发公钥状态和 Ed25519 签名；检查 `credential_id` 未消费；读取该地址领取状态并计算本次整数金额；按区块时间读取并消费当日 210 MM 全网额度；检查领取池余额；执行模块账户至领取者的 `x/bank` 转账；在同一缓存上下文内写入 `ClaimRecord`、`UsedCredential`、`DailyDistribution` 和领取池余额。任一步失败都必须回滚，不能出现“凭证已消费但未转账”“超额后仍消耗当日额度”或“转账后未记录”的状态。

## 先决冲突：全量领取池与 PoS 启动

Cosmos PoS 验证者必须存在有效的自委托质押，才能在创世后参与验证；当前开发网的三名创世验证者也正是通过预分配余额进行质押。**如果 21,000,000 MM 的每一个最小单位都锁在不可签名的领取池，创世时没有任何验证者拥有自委托，链无法以正常 PoS 方式启动。**

因此，以下三种模式必须选择一种，不能同时声称“100% 领取池”和“已启动的 PoS 验证者”：

| 模式 | 创世分配 | 对“全部免费领取”的影响 |
|---|---|---|
| A. 预留启动质押 | 少量 MM 预分配给至少三名独立验证者自委托，剩余进入领取池 | 不再是 100% 领取池，但能启动 PoS |
| B. 领取池先释放 | 创世时全量在领取池，先由领取机制向验证者地址释放到最低自委托后再启动验证者 | 创世初期没有正常 PoS 安全性；需要受控启动阶段 |
| C. 领取池托管质押 | 领取池以治理/多签控制账户持有并委托质押 | 领取池资产被锁定或承担削减风险，无法保证随时全部可领取 |

用户已授权选择 **方案 A**：正式候选创世公开预留 3 名独立验证者各 `100000000umm`（1 MM）自委托，共 3 MM；其余 `2099999700000000umm`（20,999,997 MM）唯一进入领取池。四个分配条目合计仍严格等于 `2100000000000000umm`。在发行方提供真实地址、独立运营者和主机前，仍不能生成正式 `genesis.json`，更不能启动正式网络。

## 零手续费与质押收益

交易手续费为 0 意味着没有手续费收入可分配给验证者或委托人。候选应用已移除 `x/mint`，链也不能通过自动新增 MM 支付区块奖励。因此正式网候选必须显示：**质押没有自动 MM 收益**。验证者只能自愿运行、接受链外资助，或由后续经明确同意的规则改变费用模型；不能在钱包里承诺不存在的收益。

## “谁也不能更改”的技术边界

可以通过创世检查、禁用 mint 权限、移除/限制会改变经济参数的链上治理消息、固定已审计二进制和记录创世哈希，来保证没有**当前链上授权路径**可以新增供应量。但任何公开区块链的参与者仍可选择运行修改后的软件并形成硬分叉；这属于协议外的社会共识，不可能由代码保证“全世界任何人永远不能改变”。正式说明必须准确表述为：

> 原始猫猫币正式网候选在创世时固定为 21,000,000 MM；当前协议不提供链上增发权限。任何改变供应规则的软件分叉均是不同网络，不是原始猫猫币链。

## 实现与验证顺序

1. 已选择方案 A；发行方仍须提供最终领取池地址、3 名独立验证者地址/共识公钥与长期主机。
2. 正式 chain ID 尚未选择；正式创世必须使用新生成密钥并移除开发网水龙头和所有测试 keyring。
3. 已实现 Ed25519 凭证规范编码、地址/chain ID 绑定、过期验证、篡改/跨链拒绝和凭证编号一次性消费，并由 `x/claim` 实际调用。
4. 已实现并生成 `tx.proto`、`query.proto`、keeper、模块账户、创世导入导出、消息服务和查询服务；真实 `MsgClaim` 在隔离候选节点上完成存量领取池转账。
5. 已完成一验证者隔离 E2E：首领、提前/跨链/重放拒绝、领取池扣减、供应守恒和验证者重启恢复；可控区块时间单元测试覆盖 24 小时翻倍、末笔截断和 1 MM 上限。正式发布前仍须以至少三名独立运营验证者做多节点候选网、并发与故障恢复回归。
6. 对模块、创世、二进制供应链、资格服务密钥管理和 RPC 防护完成独立安全审计后，才可请求正式创世确认。
