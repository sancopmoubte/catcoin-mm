# 猫猫币钻石皮书

> **版本：候选实现说明 v0.1。** 本文公开猫猫币（MM）当前代码、经济约束与治理边界。它不是正式主网公告、代币出售文件、收益承诺、法律意见或商标登记/放弃文件。除非“正式发布门槛”一节全部满足并由发行方明确确认，否则任何网络都只能称为**开发网或正式网候选**。

## 摘要与可核验范围

猫猫币选择 **Cosmos SDK + CometBFT 的 PoS（权益证明）** 路线，而不是复制 Bitcoin 或 Dogecoin 的 PoW、Scrypt 或 AuxPoW。该路线使用验证者和委托质押产生共识权重；CometBFT 的已知加权验证者集合在超过三分之二权重签名后提交区块，并在恶意或故障权重低于三分之一的假设下提供安全性与活性保证。[1]

当前仓库同时包含两个严格隔离的部分。`catcoin-pos-1` 是可重建的 **6 位精度开发网**，可实际完成转账、委托和官方 Tendermint/CometBFT Rust 轻客户端验证；其测试 MM 没有价值。`chain/catcoin-app` 是独立、可由本仓库追踪的 **8 位精度正式网候选应用**。候选应用已编译，并已在隔离节点中实际广播 `MsgClaim`；它不是已发布、持久运行或可交易的正式主网。

| 范围 | 已实现且已自动验证 | 不能据此宣称 |
|---|---|---|
| 开发网 | 三验证者 PoS、零费转账、委托、21,000,000 MM 的开发创世供应、Rust 轻客户端验证 | 正式网络、真实资产或永久 RPC |
| 正式网候选应用 | 独立 `catcoind`、`x/claim` Protobuf/交易/查询、创世领取池、Ed25519 凭证、链上防重放、无 `x/mint` 模块 | 已有正式 chain ID、正式创世、审核完成或交易所可用 |
| Safari/PWA 钱包 | 本地创建或导入助记词、加密本地存储、开发网余额、转账、委托、测试币入口 | 正式 MM 领取或正式主网资产操作 |

## 协议架构

候选节点基于固定的 Cosmos SDK v0.50.15 和其使用的 CometBFT v0.38.20 基线构建。Cosmos SDK 模块经 keeper 读写各自的 KVStore；交易成功时写入提交状态，失败时缓存写入会被丢弃。[2] `x/claim` 利用该原子执行语义，在同一笔交易内检查资格、计算金额、从预存领取池转账、写入领取记录并标记凭证已用。

候选链对交易、状态和创世使用 Protobuf 二进制编码；一致的确定性编码是验证者得到同一 AppHash 的前提。[3] `MsgClaim` 的签名者字段由 `cosmos.msg.v1.signer` 注解定义，领取人必须用与凭证中地址相同的钱包签名。交易签名的 chain ID 与账户序列号也属于签名材料，可防止普通交易跨链或重复广播。[3]

```text
Safari/PWA（开发网） ────► catcoin-pos-1 临时 RPC
                                  │
                            转账 / 委托 / 轻客户端验证

正式网候选钱包（尚未开放） ─► 独立 catcoind 候选应用
                                  │
                   MsgClaim（地址签名 + Ed25519 资格凭证）
                                  │
      x/claim: 校验 → 计算 → 领取池转账 → 记录领取/消费凭证
                                  │
                     IAVL 提交状态与可验证 AppHash
```

## 供应、单位与不可增发边界

正式网候选使用最低面额 `umm`（技术标识必须为小写；用户可称作 **uMM**），显示币种为 `mmc`，界面符号为 **MM**。正式网候选精度固定为 8 位：

\[
1\ \mathrm{MM}=100{,}000{,}000\ \mathrm{umm};\qquad 1\ \mathrm{umm}=0.00000001\ \mathrm{MM}
\]

| 项目 | 候选锁定值 | 实施方式 |
|---|---:|---|
| 最大与创世供应 | 21,000,000 MM | `2,100,000,000,000,000 umm` 的一次性创世分配 |
| 后续增发 | 0 MM | 候选应用已移除 `x/mint` keeper、模块、模块账户与存储键；`x/claim` 只从既有余额转账 |
| 网络手续费 | 0 MM | 候选及当前开发网最低 Gas 价格为 `0umm`；交易仍可能消耗执行 gas，但不会收取 MM 作为费用 |
| 自动质押收益 | 0 MM | 零费用且无增发，不承诺 MM 区块奖励、年化或固定回报 |
| 领取池 | 20,999,997 MM | 创世时存入 `claim` 模块账户；只能作为既有 MM 发放 |
| 启动自委托 | 3 × 1 MM | 三名**独立**验证者各 1 MM，总计 3 MM；真实地址尚未填写 |

上述四项创世分配（3 笔验证者自委托与 1 笔领取池）精确相加为 21,000,000 MM。模板和校验器拒绝开发网水龙头、测试密钥、占位符、错误精度、错误总额或多余分配项。可运行 `make verify-mainnet-candidate` 对拟定的真实分配文件做机械核验；该命令不会创建网络、转账或发行资产。

“谁也不能更改”在技术上必须诚实表述：当前候选协议没有链上增发消息、没有 `x/mint` 自动铸币模块，且领取不增加总供应；因此**遵循本二进制的原网络不能通过正常交易增发 MM**。但任何开源区块链都可能有人修改源码并说服节点运行另一套二进制；那是硬分叉或另一网络，不是对原网络历史的改写。正式发布前，必须公开二进制、创世 JSON、哈希与复现构建记录，才能让用户独立辨别所连接的网络。

## 免费领取与防批量地址规则

领取池不是水龙头铸币器。它只保管创世时已经存在的 MM，并由 `x/claim` 从模块账户转给合格地址。每个地址的领取规则由纯整数计算，避免浮点误差。

| 字段 | 候选规则 |
|---|---|
| 首次领取 | `1 umm`，即 `0.00000001 MM` |
| 间隔 | 上一次成功领取后至少 86,400 秒（24 小时） |
| 下一次金额 | 对该地址的成功领取序号按 `1, 2, 4, 8, … umm` 翻倍 |
| 地址终身上限 | `100,000,000 umm`，即 1 MM |
| 最后一笔 | 若原定翻倍额会超过剩余上限，则自动截断为剩余额 |
| 达到上限 | 永久拒绝后续领取 |
| 全网每日额度 | 每个 UTC 日最多分发 `21,000,000,000 umm`（210 MM）；当日剩余额度不足本笔时整笔拒绝，次日从零重新计数 |
| 资金来源 | `claim` 模块账户的剩余 `umm`；余额不足时拒绝，绝不铸币 |

前十次成功领取的累计额为 1,023 umm，即 0.00001023 MM。第 27 次会被截断，使累计值恰好达到 1 MM；第 28 次必须拒绝。每日 210 MM 是从同一固定领取池转出的**分发速率上限**，不是每日增发；它限制同一日内批量资格或批量地址可消耗的总量，且不会改变 21,000,000 MM 总供应。候选模块单元测试以可控区块时间覆盖翻倍、时间限制、截断、地址上限、同日超额拒绝和跨 UTC 日统计重置；隔离节点端到端测试覆盖首次领取、当日额度查询、时间不足拒绝、跨链凭证拒绝、重复凭证拒绝、领取池扣减、固定供应和节点重启后的持久化。

### 为什么“每地址最多 1 MM”不足以防刷

任何人都可以离线生成很多地址。因此仅按地址限额不能证明“一个现实世界的人只能领取一次”。候选实现增加了**链下资格审核 + 链上可验证的一次性凭证**，以提高批量地址套取的成本，但这引入中心化审核和隐私边界，不能被包装成完全去中心化的人格证明。

资格签发方以离线保存的 Ed25519 私钥签发凭证；链上创世状态只包含相应的 Ed25519 **公钥**与 `issuer_key_id`。Go 标准库提供 Ed25519 签名与验证实现；候选模块只调用验证，不保存、传输或生成正式签发私钥。[4]

凭证的规范载荷为：

```text
catcoin.claim.v1|chain_id|address|credential_id|expires_at|issuer_key_id
```

| 检查 | 链上强制结果 |
|---|---|
| `MsgClaim` 签名者与凭证地址不一致 | 拒绝 |
| 凭证的 `chain_id` 与当前链不一致 | 拒绝 |
| 已过 `expires_at` | 拒绝 |
| `issuer_key_id` 未在创世公钥集合中匹配 | 拒绝 |
| Ed25519 签名无效或载荷任一字节被篡改 | 拒绝 |
| `credential_id` 已被领取使用 | 拒绝并保持领取池不变 |
| 领取频率、地址累计上限、当日 210 MM 全网额度或领取池余额不满足 | 拒绝并保持状态原子性 |

成功领取会将 `credential_id` 写入 `UsedCredential`，并将地址累计领取额、成功次数与最后领取 Unix 时间写入 `ClaimRecord`。候选 E2E 会重启节点后再次提交同一凭证，仍被拒绝，证明记录进入了提交状态而非进程内存。Cosmos SDK 的提交 KVStore/IAVL 状态会跨区块及节点重启保存，并纳入 AppHash。[2]

### 审核、隐私与申诉：当前必须公开的未决项

代码能验证凭证，不会自动确定“哪个人值得一张凭证”。正式发布前，发行方必须公开可审计的资格标准、最小数据收集原则、数据保存期限、拒绝理由、人工复核与申诉渠道、签发方责任人、密钥轮换/撤销流程、异常领取冻结的权限与期限。当前候选源码**没有**链上 `MsgUpdateClaimAuthority` 或 `MsgRevokeCredential`；因此签发公钥、轮换和撤销的正式规则仍是发布前阻塞项，不能假称已经由治理实施。

用户不应将助记词、私钥、身份证明或身份材料提交给网页中的测试币入口。开发网的公开水龙头、确定性测试密钥和临时 RPC 被明确禁止进入正式创世。

## PoS、验证者与轻客户端

PoS 只用于共识权重和网络安全，不代表 MM 会自动产生投资回报。验证者运行节点、提议区块和签名投票；委托人可把 MM 委托给验证者以参与 PoS 权重。CometBFT 将超过三分之二验证者权重的签名集合视为提交证明，并要求少于三分之一权重为恶意或失效以维持其安全/活性假设。[1]

当前仓库的开发网回归通过官方 `cometbft/tendermint-rs` 轻客户端对可信高度、签名头、验证者集合和后续状态迁移进行验证，不把 RPC 返回当作无条件真实。正式钱包仍需要在稳定域名、可信根、见证节点与升级策略确定后，才可切换为正式模式。

正式网不应在同一台临时机器上运行三名“独立”验证者。至少三名验证者必须属于独立运营主体、不同故障域、不同运维账户和独立共识密钥；还需要哨兵、备份、恢复演练、监控、限流、TLS/DDoS 防护和受代理保护的公开 RPC。Cosmos 官方节点文档建议公共端点置于可执行负载控制或鉴权的代理后；验证者还需要防范停机和双签。[5] [6]

## 治理宪章与权限边界

候选应用包含 Cosmos `x/gov`，该通用模块可支持提案、押金、投票与通过后的消息执行；默认模型使用质押权重，委托人可覆盖验证者投票。[7] 但“代码包含通用治理模块”不等于“任何人可以改变任何规则”。本节区分已由代码锁定的规则、尚未实现的治理接口和必须由社会流程完成的事项。

| 决策类别 | 当前候选状态 | 可以改变的方式 | 发布前要求 |
|---|---|---|---|
| 总供应、`x/mint`、领取资金来源 | 无链上增发路径；领取仅转移存量 | 只能通过节点主动采纳不同二进制的硬分叉；不会追溯改写原网络 | 在创世时公开二进制、哈希与拒绝新增铸币的审计范围 |
| 领取公式、1 MM 地址上限、24 小时间隔 | 写死在 `x/claim` 候选逻辑，当前无参数更新消息 | 只能经显式协议升级/硬分叉 | 披露升级阈值、兼容性与用户迁移后果 |
| 资格签发公钥 | 创世状态写入公钥；私钥不在链上 | 当前无链上轮换/撤销交易 | 确定多签或门限签发、轮换和紧急撤销治理方案 |
| 凭证审核与申诉 | 链下运营流程，尚未最终定义 | 签发组织的公开制度与可审计记录 | 发布资格标准、隐私政策、申诉和监督机制 |
| 验证者准入、版本升级、漏洞响应 | 需要网络运营治理；当前不能声称已建成 | 多方运营者按公开升级程序运行经审计二进制 | 公开联系人、停机/双签处理、升级投票与紧急程序 |
| 品牌和开源 | 本文授予开放使用许可；代码为 Apache-2.0 | 依据许可文本与适用法律 | 由权利人和律师确认本地法律效力 |

> **治理原则：** 任何试图增加 MM、将领取池换成铸币、把测试网称为正式网、隐瞒资格审核数据用途，或在没有公开升级与节点支持的情况下声称“治理已通过”的行为，都不符合本钻石皮书。

建议的正式发布治理流程是：先公开源代码与可重复构建说明；再公布创世候选、三名验证者主体、领取签发公钥和审核制度；至少两名独立复核人检查地址与哈希；对二进制与创世制品做签名；在公开观察期内接受安全审查；最后由独立验证者分别启动并验证同一创世哈希。任何创世地址、网络标识、共识公钥或正式升级的变更都必须重新进入该流程。

## 可复现代码与测试

根仓库采用 Apache-2.0 许可；上游 Cosmos SDK 与 tendermint-rs 保留其原有许可证和归属。候选应用与其协议源文件位于 `chain/catcoin-app/`，而不是仅修改上游 Git 子模块，因此可以随主仓库一同审计与提交。

| 命令 | 验证目标 | 不会做什么 |
|---|---|---|
| `make test-pos` | 既有三验证者开发网：真实转账、零费、委托、固定供应与 Rust 轻客户端 | 不能创建正式网 |
| `make claim-policy-test` | 领取整数公式与 Ed25519 凭证候选规则 | 不能证明现实身份唯一性 |
| `make claim-e2e` | 隔离 8 位候选链：真实 `MsgClaim`、领取池转账、供应守恒、拒绝路径与重启持久化 | 不能生成正式创世或真实代币 |
| `make verify-mainnet-candidate` | 拟议正式创世模板的总量、精度、四项分配和污染标记 | 不能替代人工地址复核 |
| `make verify-claim-authority` | 公钥模板不含私钥、种子、助记词或占位符 | 不能替代签发方运营制度 |

运行候选应用前需安装与项目锁定版本匹配的 Go、`protoc`、`protoc-gen-gogo` 与 `protoc-gen-gocosmos`。`chain/catcoin-app/scripts/generate-proto.sh` 会从仓库中的 `.proto` 源重新生成类型；生成文件不得手工编辑。Cosmos SDK 明确将 Protobuf 代码生成用于跨语言的消息、查询和服务接口。[3]

## 正式发布的不可跳过门槛

在下列项目全部完成前，任何人均不得把代码、网页域名、临时节点或开发网测试币宣传为“正式猫猫币”。

1. 发行方必须在离线受控环境填入唯一正式 chain ID、3 名独立验证者的真实运营/共识地址以及唯一领取池地址，并经 `make verify-mainnet-candidate` 和人工复核通过。
2. 至少三名独立运营主体必须提供持久主机、哨兵、独立密钥管理、TLS/代理、监控、备份与恢复演练；当前沙盒和开发网的临时 URL 不合格。
3. 资格审核方必须公布审核、隐私、申诉、签发、轮换、撤销与事件响应政策，并把正式公钥写入创世；正式私钥不得出现在源码、网页、创世文件、日志或测试样例。
4. 需要独立安全审计，至少覆盖创世供应、`x/claim` 原子性、签名域分离、重放防护、密钥流程、P2P/RPC 暴露与钱包签名链路。
5. 发行方必须就不可逆的创世分配、零手续费下的验证者运营模式、升级治理和正式发布时间作出单独、明确确认。GitHub 上传、测试通过或本文发布均不是该确认。
